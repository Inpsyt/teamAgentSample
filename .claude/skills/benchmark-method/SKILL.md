# 벤치마킹 방법론 (benchmark-method)

APQC(미국생산성품질센터)의 표준 벤치마킹 프로세스 4단계를 따른다.

## 1. APQC 4단계 프로세스

| 단계 | 할 일 |
|---|---|
| ① 계획 (Plan) | 벤치마킹 목적(무슨 의사결정을 위한 비교인가)을 문서 서두에 명시. 비교 축·지표를 먼저 정의하고, 대상 선정 기준(직접 경쟁/유사 모델/선진 사례)을 밝힌다 |
| ② 수집 (Collect) | 대상별로 동일한 축을 조사해 매트릭스를 채운다. 셀마다 출처 필수, 확인 불가는 `미확인` |
| ③ 분석 (Analyze) | 격차 분석: 기준 대상 대비 우위/열위/동등을 판정하고, 격차의 **원인이 되는 관행(enabler)**을 파악한다 — "A사가 앞선다"에서 멈추지 않고 "무엇을 하기에 앞서는가"까지. 자사 제품이 없는 신규 기획이면 계획 단계에서 선언한 기준 대상(가장 유사한 경쟁 서비스 또는 목표 스펙)을 기준으로 삼는다. enabler가 공개 자료로 확인 불가하면 `미확인`으로 두되, 이를 근거로 한 시사점은 **가설임을 명시**한다 |
| ④ 적응 (Adapt) | 시사점: 그대로 이식이 아니라 자사 맥락에 맞춘 적용안을 제언. 각 제언은 ③의 분석 결과와 1:1로 연결한다 |

## 2. 벤치마킹 유형 (계획 단계에서 선언)

- **경쟁 벤치마킹**: 동일 시장 직접 경쟁사 비교 (기능·가격·포지셔닝)
- **기능 벤치마킹**: 산업이 달라도 특정 기능·프로세스가 뛰어난 사례 비교 (예: 타 업종의 온보딩 UX)
- **내부 벤치마킹**: 자사 내 다른 제품·팀과 비교

요청이 "경쟁사 비교"라도 목적에 따라 기능 벤치마킹 대상을 1개 이상 포함하면 시사점이 풍부해진다.

## 3. 비교 매트릭스 설계 원칙

- **축은 MECE로**: 겹치거나 빠진 축이 없게. 대분류(기능/가격/UX/시장 지위) → 세부 축 순으로 설계
- **정규화**: 가격은 동일 조건(동일 인원·기간·환율 기준일)으로 환산해 비교. 환산 기준을 표 아래에 명시
- **사실과 해석 분리**: 매트릭스 셀에는 확인된 사실만, 우위/열위 판정과 해석은 별도 분석 섹션에 쓴다
- **비교 시점 명시**: 요금제·기능은 자주 바뀐다. 각 대상의 확인 일자를 기록한다

## 흔한 실수

- 축 정의 없이 대상별 특징을 나열 → 비교 불가능한 서술문 모음이 됨
- 격차 원인(enabler) 분석 없이 "벤치마킹하자"는 시사점 → ③을 건너뛴 결과물
- 무료 플랜과 유료 플랜을 정규화 없이 같은 행에서 비교
- 시사점이 매트릭스에 없는 근거에서 도출됨 (근거 없는 제언 금지 규칙 위반)
