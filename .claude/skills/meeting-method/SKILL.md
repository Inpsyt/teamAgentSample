# 회의 방법론 (meeting-method)

## 작업 절차 — 회의 전 (아젠다)

1. `doc-conventions`, `doc-templates`, `task-format`, 이 스킬을 로드한다
2. `workspace/` 전체에서 회의 주제 관련 문서를 검색해 "사전 참고 자료"로 링크한다
3. "회의 아젠다" 템플릿으로 `workspace/40-meetings/YYYY-MM-DD-<회의명>-아젠다.md`에 저장한다
4. 안건별로 "결정이 필요한 사항"을 명시한다 — 아젠다의 핵심은 결정 유도다

## 작업 절차 — 회의 후 (회의록)

1. 전달받은 녹취/메모에서 결정사항·액션아이템·보류 항목을 추출한다
2. "회의록" 템플릿으로 `workspace/40-meetings/YYYY-MM-DD-<회의명>-회의록.md`에 저장한다
3. 액션아이템은 task-format 형식(`- [ ] <내용> @담당자 ~기한 #프로젝트`)으로 쓴다. 담당자·기한이 메모에 없으면 `@미정`, `~미정`
4. 액션아이템은 SMART 기준으로 다듬는다 — 구체적, 완료 판정 가능, 기한 명시. "검토한다"·"논의한다"는 산출물 단위로 바꾼다 (예: "일정 검토" → "일정 검토 의견을 회신")

## 규칙

- 메모에 없는 결정사항을 만들지 않는다. 불명확한 부분은 "보류·추후 논의"에 넣는다
- 태스크 보드 이관은 직접 하지 않는다 — 최종 응답에 "액션아이템 N건, 보드 이관 필요"를 명시하면 PM이 schedule 작업을 순차 위임한다
- front-matter: `agent: meeting`, 아젠다 `status: 초안`, 회의록 `status: 확정`
