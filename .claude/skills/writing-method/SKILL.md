# 문서 작성 방법론 (writing-method)

Barbara Minto 『The Pyramid Principle』의 논리 구조화 원칙을 따른다.

## 1. 피라미드 원칙 (모든 문서 공통)

- **결론 우선(답 먼저)**: 문서·섹션·문단 모두 핵심 주장을 첫 문장에 쓰고, 근거를 뒤에 붙인다. 근거를 쌓다가 마지막에 결론이 나오는 구조 금지
- **MECE 그룹핑**: 같은 층위의 항목(근거 3개, 대안 3개)은 서로 겹치지 않고 합치면 전체가 되게 묶는다
- **수직 논리**: 상위 주장에 "왜?"라고 물으면 바로 아래 항목들이 답이 되어야 한다. 답이 안 되는 항목은 다른 가지로 옮기거나 삭제
- **근거 개수**: 한 주장 아래 근거는 2~4개. 5개 이상이면 그룹핑이 덜 된 것

## 2. SCQA 도입부 (기획서·제안서)

배경 섹션은 SCQA 순서로 쓴다:

- **S (상황)**: 독자가 동의하는 현재 상태
- **C (문제)**: 상황을 흔드는 변화·문제 — 왜 지금 이 문서인가
- **Q (질문)**: 그래서 무엇을 해야 하는가 (명시적으로 쓰지 않아도 됨)
- **A (답)**: 이 문서의 제안 — 한 문장으로

기획서 본문 흐름: 배경(SCQA) → 목표(정량 지표 포함) → 해결 방안 → 실행 계획 → 기대 효과·리스크. 제안서는 같은 흐름을 **고객(독자)의 이익 관점**으로 서술한다 — "우리가 할 수 있는 것"이 아니라 "고객이 얻는 것" 주어로.

## 3. 주간보고 — PPP 프레임

- **Progress (진척)**: 이번 주 완료한 것 — 산출물 링크 필수
- **Plans (계획)**: 다음 주 할 것 — 태스크 보드와 일치
- **Problems (문제)**: 지연·리스크·의사결정 필요 사항 — 요청사항을 명시

성과 없는 주라도 Problems를 비우지 않는다 — 문제가 없으면 "없음"을 명시해 확인했음을 남긴다.

## 4. 경영진 요약 원칙

- 1페이지 이내, 서술형 결론 먼저 (doc-conventions §6 "요약 우선" 규칙의 확장)
- 구조: 결론 1문장 → 핵심 근거 2~3개 → 요청·결정 필요 사항
- 경영진이 그 자리에서 결정할 수 있게 **선택지와 권고안**을 제시한다 ("검토 바랍니다"로 끝내지 않는다)

## 흔한 실수

- 근거 나열 후 마지막에 결론 (결론 우선 위반) — 특히 조사 인용이 많을 때 발생
- 배경 섹션이 S만 있고 C가 없음 → "왜 지금 하는가"에 답하지 못하는 기획서
- 목표에 정량 지표 없음 ("사용성 개선" 같은 측정 불가 목표)
- 주간보고 Problems 누락 → 지연이 보고 없이 누적됨
