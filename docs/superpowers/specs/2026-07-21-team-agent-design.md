# 기획업무 팀 에이전트 설계

- 작성일: 2026-07-21
- 상태: 확정
- 프로젝트: teamAgent

## 1. 목적

기획 실무 산출물 생산과 웹 프로젝트 기획·관리를 모두 커버하는 로컬 에이전트 팀을 구성한다.
사용자는 메인 세션에 자연어로 요청하고, 메인 세션(PM)이 역할별 전문 에이전트에게 위임한다.

- 산출물 저장: 로컬 마크다운 파일만 사용 (외부 서비스 연동 없음)
- 호출 방식: PM 오케스트레이터 중심 자동 위임 + 사용자의 직접 에이전트 지명 허용

## 3. 에이전트 9개 상세

| 에이전트 | 역할 | 주요 도구 | 산출물 위치 |
|---|---|---|---|
| research | 리서치·자료조사 | WebSearch, WebFetch, Read, Write | `10-research/` |
| benchmark | 벤치마킹·경쟁분석 | WebSearch, WebFetch, Read, Write | `10-research/` |
| draft | 초안작성 | Read, Write, Edit | `20-drafts/` |
| data | 데이터 취합·정리 | Read, Write, Bash(간단 집계) | `30-data/` |
| meeting | 회의준비·회의록 | Read, Write, Edit | `40-meetings/` |
| schedule | 업무일정 관리 | Read, Write, Edit | `50-schedule/` |
| web-planning | 웹기획 | Read, Write, WebSearch(레퍼런스) | `60-web-planning/` |
| report | 보고·커뮤니케이션 | Read, Write | `70-reports/` |
| archive | 아카이빙 | Read, Write, Bash(파일 이동) | `90-archive/` |

### research (리서치·자료조사)

질문 접수 → 검색 → 출처 수집 → 교차 검증 → 보고서 작성 흐름.
모든 주장에 출처 URL을 달고, 확인되지 않은 내용은 "미확인"으로 명시한다.
사용자 요청의 "리서치"와 "자료조사"는 동일 작업 흐름이므로 하나로 통합.

### benchmark (벤치마킹·경쟁분석)

research와 도구는 같지만 산출물 구조가 다르다:
비교 기준표 정의 → 경쟁사별 조사 → 비교 매트릭스 + 시사점 도출.
기능 비교 / 가격 비교 / UX 흐름 비교 등의 정형 포맷을 갖는다.

### draft (초안작성)

기획서·제안서·요구사항 정의서 등의 초안 작성.
백지에서 쓰지 않고, 먼저 `10-research/`, `30-data/`의 기존 자료를 검색해 근거로 인용한다.
문서 유형별 템플릿은 `doc-templates` 스킬에 정의.

### data (데이터 취합·정리)

여러 소스(파일, 붙여넣은 표, 조사 결과)를 마크다운 표로 정규화.
수치가 있으면 합계·평균 등 기본 집계를 Bash로 검증해 계산 오류를 방지한다.

### meeting (회의준비·회의록)

- 회의 전: 아젠다 + 관련 자료 요약 + 논의 포인트 패키지 생성
- 회의 후: 녹취/메모를 받아 결정사항·액션아이템(담당자·기한 포함) 중심의 회의록 정리
- 액션아이템은 `task-format` 스킬의 형식으로 기록해 schedule 에이전트가 읽을 수 있게 한다

### schedule (업무일정 관리)

`50-schedule/tasks.md`(전체 태스크 보드)와 프로젝트별 WBS를 관리.
회의록의 액션아이템, 각 산출물의 후속 작업을 태스크로 등록한다.
"오늘 할 일 정리해줘" 요청 시 마감 임박·지연 항목을 보고한다.

### web-planning (웹기획)

IA(사이트맵), 화면 정의서, 기능 요구사항, 유저 플로우를 마크다운 + mermaid 다이어그램으로 작성.
화면 정의서는 화면ID·구성요소·인터랙션·예외케이스 형식의 정형 포맷.

### report (보고·커뮤니케이션)

주간보고, 경영진 요약(1페이지), 이해관계자별 맞춤 요약.
workspace 전체를 읽고 기간 내 산출물·진행상황을 취합하는 것이 핵심이라 별도 에이전트로 분리.

### archive (아카이빙)

완료된 프로젝트 산출물을 `90-archive/<프로젝트명>/`로 이동하고,
`90-archive/INDEX.md`에 색인을 유지한다.
"예전에 OO 조사했던 거 찾아줘" 같은 과거 산출물 검색 요청도 담당.

### 에이전트 간 연결 규칙

에이전트끼리 직접 호출하지 않는다. 항상 PM(메인 세션)이 순서를 정해 위임한다.
예: 회의록 작성(meeting) 후 액션아이템 등록(schedule)은 PM이 순차 위임.
흐름 추적 가능성 확보와 무한 위임 방지가 목적.

## 4. PM 오케스트레이터 규약 (CLAUDE.md)

1. **위임 매핑** — 요청 유형별 담당 에이전트 기준표.
   조사·검색 → research, 경쟁사·비교 → benchmark, 문서 초안 → draft,
   데이터 정리 → data, 회의 관련 → meeting, 일정·태스크 → schedule,
   IA·화면·요구사항 → web-planning, 보고·요약 → report, 정리·검색(과거) → archive.
   애매하면 사용자에게 되묻지 않고 가장 가까운 에이전트에 위임하되, 위임 내용을 한 줄로 보고한다.
2. **분해·병렬 규칙** — 복합 요청은 독립 작업으로 쪼개 병렬 위임,
   의존성 있는 작업(예: 회의록 → 액션아이템 등록)은 순차 위임. 에이전트 간 직접 호출 금지.
3. **품질 확인** — 산출물이 명명규칙·템플릿을 따랐는지, 출처가 달렸는지 PM이 확인 후 보고.
   미흡하면 해당 에이전트에 재작업 위임.
4. **직접 지명** — 사용자가 특정 에이전트를 지명하면 매핑과 무관하게 그대로 위임.
5. **일일 브리핑** — "오늘 뭐 해야 해?" 류 요청 시 schedule의 태스크 보드 +
   최근 산출물 상태를 종합해 브리핑.

## 5. 공용 스킬 3개

### doc-conventions (문서 규약)

모든 에이전트가 산출물 작성 전 로드.

- 명명: `YYYY-MM-DD-<주제>.md`, 폴더별 저장 위치 규칙
- front-matter: 제목·작성 에이전트·상태(초안/검토중/확정)·관련 문서 링크
- 출처 표기: 웹 자료는 URL+접속일, 내부 자료는 파일 경로
- 한국어 문서 작성 원칙: 개조식 기본, 경영진 대상은 서술형 요약 우선

### doc-templates (문서 템플릿)

유형별 정형 템플릿 모음.

- 기획서 / 제안서 / 요구사항 정의서 (draft용)
- 리서치 보고서 / 경쟁분석 매트릭스 (research·benchmark용)
- 회의 아젠다 / 회의록 (meeting용)
- 화면 정의서 / IA 문서 (web-planning용)
- 주간보고 / 1페이지 경영진 요약 (report용)

### task-format (태스크·액션아이템 규약)

meeting과 schedule이 공유하는 형식.

- 액션아이템: `- [ ] <내용> @담당자 ~기한 #프로젝트` 형식
- `50-schedule/tasks.md` 보드 구조: 대기 / 진행중 / 완료 / 지연
- 회의록의 액션아이템이 태스크 보드로 이관되는 규칙 (PM이 meeting → schedule 순차 위임으로 수행)

## 6. 기존 설치 스킬 활용 (작성 불필요)

- **deep-research** — research 에이전트로 부족한 심층·다출처 검증 리서치가 필요할 때 PM이 대신 호출
- **dataviz** — data 에이전트가 차트·시각화 산출물을 만들 때 참조
- **ax-docx / ax-pptx** — 외부 제출용 최종본이 필요할 때만 사용자가 명시 요청으로 변환 (규약 미포함, 선택사항)

## 7. 에러 처리·경계 사례

- 에이전트가 산출물 규약을 어기면 PM이 재작업을 위임한다 (최대 1회, 그래도 미흡하면 그대로 보고하고 사용자 판단에 맡김)
- 웹 검색 실패·출처 부족 시 research/benchmark는 "확인 불가" 항목을 명시하고 부분 결과라도 저장한다
- 동일 주제 파일이 이미 존재하면 덮어쓰지 않고 `-v2` 접미사로 새 버전을 만든다
- `00-inbox/`의 미분류 자료는 archive 에이전트가 정리 요청 시 적절한 폴더로 분류한다

## 8. 검증 기준

- 에이전트 9개 + 스킬 3개 + CLAUDE.md + workspace 폴더 구조가 모두 생성된다
- "OO 경쟁사 조사해줘" 같은 대표 요청이 올바른 에이전트로 위임되고, 산출물이 규약(명명·front-matter·출처)을 따른다
- 회의록 액션아이템 → 태스크 보드 이관 흐름이 동작한다
- 스킬은 사용자 슬래시 호출용이 아니라 에이전트가 로드하는 규약으로 동작한다
