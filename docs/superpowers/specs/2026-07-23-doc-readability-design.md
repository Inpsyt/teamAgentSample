# 산출물 가독성 규약 개정 — 설계

날짜: 2026-07-23
상태: 승인됨 (사용자 확인)

## 문제

workspace 산출물이 훑어보기·정독 모두 힘들다. 원인은 문서 규약 자체에 있다:

1. **인라인 전체 경로 인용** — doc-conventions §4가 "내부 자료는 workspace 상대 경로로 표기"라고 규정해, `(workspace/10-research/2026-07-21-...-기술조사.md, §a)` 같은 인용이 문장 중간에 반복 등장하며 읽기 흐름을 끊는다.
2. **정보 압축 덩어리 문장** — 불릿 하나에 괄호·줄표·화살표·인용이 3~4겹 중첩.
3. **표 셀 안의 문단** — QA 리포트 이슈 표의 셀 하나가 4~5문장. 표의 한눈 비교 기능 상실.
4. **강조 과잉·결론 후치** — 볼드가 거의 매 불릿에 있고, 기획서류는 결론이 문서 중반에야 등장.

`[확인 필요]` 마커와 출처 의무 등 엄밀함 장치가 읽기 경험보다 우선된 규약이 근본 원인. 엄밀함 요구는 유지하되 **위치를 옮긴다**.

## 확정된 요구사항 (사용자 답변)

- 훑어보기·정독 모두 개선 (구조 + 문장 스타일)
- 출처는 **각주형** — 본문 `[1]` 번호, 말미 출처 섹션
- **모든 문서 상단 요약 의무화** (별도 공유본 파일은 만들지 않음)
- 접근: B안 — doc-conventions + doc-templates 동시 개정 + review 게이트 추가

## 설계

### 구성 1 — doc-conventions 개정 (규칙)

`.claude/skills/doc-conventions/SKILL.md`

**§4 출처 표기 → 각주형 전환:**
- 본문에는 `[1]`, `[2]` 번호만 남긴다. 웹·내부 자료 모두 전체 경로/URL은 문서 말미 `## 출처` 섹션에 번호 목록으로만 표기.
- 출처 섹션 형식: `[1] <제목> — <workspace 경로 또는 URL> (웹은 접속일 포함)`
- `[확인 필요]` 마커는 본문에 짧게만 붙이고, 사유·후속 계획 등 긴 설명은 "미확인·추가 조사 필요" 섹션에 모은다.

**신설 §6 가독성 규칙:**
- **요약 우선**: front-matter 바로 아래 `## 요약` — 결론·핵심 근거·다음 액션 3줄. 모든 산출물 공통.
- **불릿 1개 = 1문장** (최대 2문장). 길어지면 하위 불릿으로 분할.
- **괄호 중첩 금지**: 괄호 안 괄호 금지, 한 문장에 괄호 2개 이상 금지. 부연이 길면 별도 문장으로.
- **표 셀은 구절 단위**: 셀에 2문장 이상 필요하면 표 대신 소제목+불릿. 재현 절차·상세 근거는 표 아래 본문에.
- **볼드는 섹션당 최대 2회** — 결론에만.

### 구성 2 — doc-templates 개정 (예시)

`.claude/skills/doc-templates/SKILL.md`

- 공통 머리말에 "모든 템플릿은 front-matter 바로 아래 `## 요약`(결론·근거·다음 액션 3줄)으로 시작" 명시.
- 요약 섹션이 없던 템플릿에 추가: 기획서, 요구사항 정의서, 회의록, 화면 정의서, IA 문서, 리뷰 노트. (이미 있는 템플릿은 형식만 3줄 규격으로 통일.)
- 각 템플릿의 `## 출처`/`## 참고 자료`에 각주형 예시(`[1] 제목 — 경로/URL`)를 실제 표기로 포함.
- QA 리포트 템플릿의 높음/중간 표에 지침 주석 삽입: 셀은 증상·제안 요지 1~2구절, 재현 절차·근거는 표 아래 불릿.

### 구성 3 — review 에이전트 게이트 (검증)

`.claude/agents/review.md`

검증 관점에 **가독성** 항목 추가:
- 상단 `## 요약` 유무
- 본문 인라인 전체 경로/URL 인용 (각주형 위반)
- 표 셀 과밀 (2문장 이상)
- 괄호 중첩

위반은 심각도 "하"(표현·형식)로 지적해 내용 문제와 등급이 섞이지 않게 한다.

## 변경하지 않는 것

- 기존 workspace 문서 8건 (필요 시 개별 재작성으로 대응)
- 출처 필수·미확인 표기 의무 등 엄밀함 요구 자체 — 위치만 이동
- CLAUDE.md의 품질 게이트 절차 (PM 형식 검사 항목은 규약 개정을 자동 반영: "출처가 달렸는가" 판정 기준이 각주형으로 바뀔 뿐)

## 검증 방법

구현 후 다음으로 확인한다:
1. 세 파일의 규칙·템플릿·게이트가 서로 모순 없는지 교차 확인 (예: 템플릿 예시가 인라인 인용을 보여주는 곳이 남아 있는지 grep)
2. 임의 유형 1건(예: 리서치 보고서)을 새 규약으로 작성 시뮬레이션해 요약·각주·표 규칙이 실제로 적용 가능한지 확인
